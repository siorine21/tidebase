## 2. 一度きりのセットアップ（合計 15 分程度）

Claude Code on the Web の**環境設定**（Environment settings）で以下を行う。
設定方法の詳細: https://code.claude.com/docs/en/claude-code-on-the-web

### 2.1 ネットワークポリシーにドメインを許可（5 分）

現在のサンドボックスは外部サイトがほぼ遮断されており、これが委任の最大のブロッカー。
環境のネットワークポリシーで以下を許可する（カスタム許可リスト方式の場合）:

| ドメイン | 用途 |
|---------|------|
| `www.data.jma.go.jp` | 潮汐データ取得・観測点マスタ生成 |
| `api.supabase.com` | Management API（マイグレーション適用・Auth 設定） |
| `*.supabase.co` | Supabase REST / Auth（結合テスト） |
| `api.open-meteo.com` / `marine-api.open-meteo.com` / `archive-api.open-meteo.com` | 天気・波高（Phase 2） |
| `*.amazonaws.com` | SAM デプロイ（CloudFormation / Lambda / S3 / SSM ほか） |

### 2.2 シークレットを環境変数に登録（10 分）

環境設定の環境変数（Secrets）に以下を登録する。**リポジトリには絶対にコミットしない**。

| 変数名 | 取得場所 |
|--------|---------|
| `SUPABASE_ACCESS_TOKEN` | supabase.com → アカウントアイコン → Access Tokens → Generate new token |
| `SUPABASE_PROJECT_REF` | ダッシュボード URL `supabase.com/dashboard/project/{この部分}` |
| `SUPABASE_URL` | Project Settings → API（`https://xxxx.supabase.co`） |
| `SUPABASE_ANON_KEY` | Project Settings → API Keys |
| `SUPABASE_JWT_SECRET` | Project Settings → JWT Keys（**レガシー HS256 の場合のみ**） |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | IAM ユーザー `yuki` のアクセスキー（Phase 0 作成済みのもの、または新規発行） |
| `AWS_REGION` | `ap-northeast-1` |

### 2.3 セキュリティ上の注意

- `SUPABASE_ACCESS_TOKEN` は**アカウント全体に効く**強い権限。個人開発の
  単一プロジェクトなら実害は限定的だが、不要になったら削除・定期ローテーション推奨
- AWS キーも同様。CloudTrail / Budgets アラート（月 $3）を張っておくと安心
- 環境変数はセッションのサンドボックス内でのみ使われ、コミット対象にならない
  （`.gitignore` 済みの `.env` にも書かない運用とする）

## 3. セットアップ後に Claude Code へ頼めること（例）

```
「マイグレーションを適用して」
  → scripts/supabase_admin.py apply（適用済み管理付き・冪等）
「スキーマの実態を確認して v1.3 と突合して」
  → scripts/supabase_admin.py inspect → 設計補完書 8 章の台帳と突合 → 差分修正
「観測点マスタを生成して」
  → scripts/generate_tide_stations.py → JSON 差し替え → テスト → コミット
「潮汐 API の実疎通を確認して」
  → 気象庁から実データ取得 → パーサー検証 → 問題あれば修正
「dev にデプロイして」
  → sam build && sam deploy → デプロイ後に /health 疎通確認
「Supabase の Auth 設定をして」
  → Management API で Email/Password 有効化・Site URL 設定
```

## 4. 進め方の推奨

1. 上記セットアップ完了を Claude Code に伝える
2. Claude Code が「スキーマ突合 → マイグレーション適用 → 観測点マスタ生成 →
   JMA 疎通確認」を一括実行（設計補完書 11 章の順序）
3. 以降は機能単位で PR を作成 → あなたはレビュー・マージのみ
