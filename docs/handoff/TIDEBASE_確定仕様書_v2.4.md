### 1.3 任意入力欄（数量記録）

エリアトラウト等、魚種の厳密な判別より釣れた数を優先して記録したい場合のために、魚種選択とは独立した任意フィールドを設ける。

| フィールド名 | 入力タイプ | 必須 | 説明 |
|------------|----------|------|------|
| 魚種 | 選択（サジェスト付き）＋自由入力 | 任意 | 初期 13 種からサジェスト。出世魚自動判定もここで発動 |
| 数量メモ（任意入力欄） | テキスト | 任意 | 「トラウト系 多数」「トラウト ×12」等を自由に記入。魚種未入力でも記録可能 |
| 匹数 | 数値 | 必須（デフォルト：1） | 厳密なカウントが分かる場合に入力 |

> ✅ ボウズ記録の場合は魚種・サイズ・匹数がすべて空でも、釣行日・スポット・天気・メモのみで登録できる。

## 4. グループ招待仕様

### 4.1 方式決定：URL シェアのみ

> ✅ グループ招待は URL シェア方式のみで実装する（メール招待は Phase 5 以降）。  
> URL を LINE・SMS・メッセンジャー等でシェアするだけで参加できる。

| 項目 | 仕様 |
|------|------|
| 招待 URL 形式 | `https://tidebase.app/join?token={UUID v4}` |
| トークン有効期限 | 7日間（`invite_tokens.expires_at`） |
| 使用回数制限 | 1 トークン 1 人まで（`used_at` が NULL の場合のみ有効） |
| 参加時のロール | デフォルト：viewer（オーナーが後から変更可） |
| 期限切れ時の挙動 | エラー画面を表示。再発行ボタンを提示 |
| トークン再発行 | グループオーナーがグループ設定画面から何度でも発行可能 |
| SES 不要 | メール送信は行わない。ユーザーが手動で URL をシェアする |

### 4.2 招待フロー

| ステップ | オーナー側 | 参加者側 |
|---------|----------|---------|
| 1 | グループ設定 → 「招待リンクを発行」をタップ | — |
| 2 | 生成された URL をコピー | — |
| 3 | LINE や SMS で参加者に送信 | — |
| 4 | — | URL をタップ（未ログインの場合はログイン/登録画面へ） |
| 5 | — | 「○○グループに参加しますか？」確認 → 参加ボタンをタップ |
| 6 | グループフィードに「○○さんが参加しました」と表示 | グループフィードが表示される |

## 5. スポット公開範囲仕様

> スポットの公開範囲はデフォルト「グループ」で実装する。  
> 「自分のみ」設定は Phase 5 で追加予定。DB スキーマには最初から `visibility` カラムを用意しておく。

| フェーズ | visibility 値 | UI 表示 | 動作 |
|---------|-------------|--------|------|
| Phase 1〜4（現在） | `'group'` | 👥 グループ | グループメンバー全員が閲覧可能。RLS で自動制御 |
| Phase 1〜4（現在） | `'private'` | （UI から選択不可） | 将来実装のために値だけ定義しておく |
| Phase 5（将来） | `'private'` | 🔒 自分のみ | 登録者本人のみ閲覧可能 |

### 釣果記録の公開範囲

釣果記録（`fishing_records`）は「自分のみ / グループ」の 2 択を Phase 1 から実装する。デフォルトは「グループ」。

| visibility 値 | デフォルト | 説明 |
|-------------|----------|------|
| `'group'` | ✅ デフォルト | グループメンバー全員が閲覧・コメント可能 |
| `'private'` | — | 登録者本人のみ閲覧可能。Phase 1 から選択可 |

## 6. ボウズ記録仕様

### 6.1 入力フロー

> 釣果入力フォームの先頭に「ボウズで記録」ボタンを配置する。  
> タップすると魚種・サイズ・ルアーの入力をスキップし、スポット・潮汐・天気・メモのみで記録できる。

| 入力ステップ | 通常入力（釣れた） | ボウズ記録 |
|------------|----------------|---------|
| フォーム先頭 | 「🎣 釣果を記録」ボタン | 「😞 ボウズで記録」ボタン（先頭に配置） |
| STEP 1 | 魚種・サイズ・匹数 | ~~スキップ~~ |
| STEP 2 | タックル・ルアーレシピ | ~~スキップ~~ |
| STEP 3 | スポット選択 | スポット選択（同じ） |
| STEP 4 | 写真 | 写真（同じ・任意） |
| STEP 5 | メモ（潮汐・天気は自動取得） | メモ（潮汐・天気は自動取得） |
| 登録後の表示 | 釣果一覧にサムネ付きで表示 | 釣果一覧に「😞 ボウズ」として表示 |

### 6.2 DB スキーマへの影響

| カラム | ボウズ時の値 | 説明 |
|-------|-----------|------|
| `is_skunked` | `TRUE` | ボウズフラグ。デフォルト `FALSE` |
| `fish_type` | `NULL`（任意） | 空でも登録可 |
| `size_cm` | `NULL` | 空でも登録可 |
| `count` | `0` | ボウズ時は 0 で保存 |
| `spot_id` | 入力した値 | スポットは記録推奨 |
| `tide_snapshot` | 自動取得 | 潮汐データは通常どおり保存 |
| `weather_snapshot` | 自動取得 | 天気データは通常どおり保存 |

> 📊 ボウズデータも統計・相関分析（潮汐×釣果）に活用する。「この潮回りはボウズ率が高い」という知見も蓄積できる。

## 8. メソッド機能仕様（F-11）

> エリアトラウト等で反応がない時に参照できるガイドライン機能。  
> SCR-010 ローテーションログ内の「メソッド」タブに表示する。

### 8.1 機能概要

| 項目 | 内容 |
|------|------|
| 表示場所 | SCR-010 ローテーションログ内「メソッド」タブ |
| 実装 Phase | Phase 2（ローテーションログと同タイミング） |
| 初期対象 | エリアトラウト |
| 将来展開 | 釣りスタイル別（ショアジギング・エギング・サーフ等）にメソッドセットを切り替え可能な設計 |

### 8.2 データ種別

| 種別 | user_id | 編集・削除 | 説明 |
|------|---------|-----------|------|
| システムデフォルト | NULL | 不可 | 全ユーザー共通の初期メソッド |
| ユーザー追加 | 自分の ID | 本人のみ可 | ユーザーが自由に追加したメソッド |

### 8.3 初期メソッド一覧（エリアトラウト）

| 状況 | 試すこと |
|------|---------|
| 反応がない（全般） | ルアーの種類を変える（スプーン→クランク→プラグ） |
| 反応がない（全般） | レンジを変える（表層→中層→ボトム） |
| 反応がない（全般） | リトリーブ速度を変える（早巻き→デッドスロー） |
| 反応がない（全般） | カラーを変える（派手→ナチュラル、またはその逆） |
| チェイスはあるが食わない | ルアーサイズを下げる |
| チェイスはあるが食わない | ストップ&ゴーを入れる |
| チェイスはあるが食わない | フックをシャープなものに交換 |
| 朝イチ・放流直後 | 表層の早巻きから試す |
| 時間が経って渋い | ボトムのデッドスロー・ステイ |
| 晴天・プレッシャー高 | ナチュラルカラー・細軸フック・軽めのスプーン |

### 8.4 DB スキーマ

```sql
CREATE TABLE public.methods (
  id          UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id     UUID REFERENCES public.profiles(id),  -- NULL = システムデフォルト
  style       TEXT NOT NULL DEFAULT 'area_trout',   -- 将来: 'shore_jigging' 等
  situation   TEXT NOT NULL,   -- 例：「チェイスはあるが食わない」
  action      TEXT NOT NULL,   -- 例：「ルアーサイズを下げる」
  sort_order  INTEGER,         -- 表示順（デフォルト → ユーザー追加順）
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- RLS
ALTER TABLE public.methods ENABLE ROW LEVEL SECURITY;

-- 全員がデフォルト（user_id IS NULL）と自分のメソッドを閲覧可能
CREATE POLICY "methods: read" ON public.methods
  FOR SELECT USING (user_id IS NULL OR auth.uid() = user_id);

-- 自分のメソッドのみ追加・編集・削除可能
CREATE POLICY "methods: own write" ON public.methods
  FOR ALL USING (auth.uid() = user_id);
```

| 7 | その他 | `other` | 小カテゴリ表示（その他） |

**小カテゴリ（下段・大カテゴリ選択時のみ表示）**

| 大カテゴリ | 小カテゴリ一覧（先頭は必ず「すべて」） |
|-----------|--------------------------------------|

| エギ | すべて / エギ / タコエギ |
| その他 | すべて / その他（自由入力） |

### 9.2 動作仕様

| 操作 | 動作 |
|------|------|
| 大カテゴリ「すべて」タップ | 小カテゴリ行を非表示にして全レシピを一覧表示 |

| 小カテゴリ「すべて」タップ | 大カテゴリ内の全種別レシピを表示 |

| ⭐ お気に入り | 大カテゴリとは独立したフィルタ。常時右端に固定表示 |

### 9.3 実装メモ

- 大カテゴリ・小カテゴリの切り替えは HTMX で部分更新
- `style` カラム（`area_trout` / `hard` / `metal` / `soft` / `egi` / `other`）と `sub_category` カラムで絞り込み
- 大カテゴリ行は横スクロール不要な幅に収める（7項目）

## 13. 潮汐×釣果相関仕様（SCR-003 追加）

### 13.1 集計仕様

| 指標 | 内容 |
|------|------|
| 釣行回数 | 該当潮汐種別での日単位セッション数（1日1釣行） |
| 釣果数 | 該当潮汐での合計釣果数 |
| スコア | 釣果数 ÷ 釣行回数（小数第1位・単位なし） |
| バー長さ | 釣行あたり釣果率を最大値で正規化（0〜100%） |

### 13.2 集計クエリ

```sql
SELECT
  tide_type,
  COUNT(DISTINCT DATE(fished_at))        AS outing_count,
  COUNT(*)                               AS catch_count,
  ROUND(COUNT(*) / NULLIF(COUNT(DISTINCT DATE(fished_at)), 0)::numeric, 1)
                                         AS score
FROM fishing_records
WHERE user_id = auth.uid()
GROUP BY tide_type
ORDER BY catch_per_outing DESC;
```

### 13.3 DB への影響

スキーマ変更不要。既存の `fishing_records.fished_at`（日付）を使用して集計クエリのみ変更。

## 14. スポット水域区分仕様（SCR-004 追加）

### 14.1 水域区分

| 区分 | 潮汐相関スコア | 含むスポット例 |
|------|-------------|-------------|
| 海水 | ✅ 対象 | 港湾・磯・サーフ |
| 汽水 | ✅ 対象 | 河口・干潟・汽水湖・河川 |
| 淡水 | ❌ 除外 | エリア・淡水湖・野池・渓流 |

### 14.2 DB スキーマ（spots テーブル追加カラム）

```sql
ALTER TABLE public.spots
  ADD COLUMN water_type TEXT NOT NULL DEFAULT 'saltwater'
  CHECK (water_type IN ('saltwater', 'brackish', 'freshwater'));
```

### 14.3 潮汐相関スコア集計への反映

```sql
SELECT
  r.tide_type,
  COUNT(DISTINCT DATE(r.fished_at)) AS outing_count,
  COUNT(*)                          AS catch_count,
  ROUND(COUNT(*) / NULLIF(COUNT(DISTINCT DATE(r.fished_at)), 0)::numeric, 1) AS score
FROM fishing_records r
JOIN spots s ON r.spot_id = s.id
WHERE r.user_id = auth.uid()
  AND s.water_type IN ('saltwater', 'brackish')  -- 海水・汽水のみ
GROUP BY r.tide_type
ORDER BY score DESC;
```

## 18. メソッド削除・編集仕様（SCR-010）

### 18.1 基本方針

システムデフォルト・ユーザー追加分を問わず、**全メソッドが編集・削除可能**。デフォルトはあくまで初期値として提供。

### 18.2 操作方法

| 操作 | 方法 |
|------|------|
| 編集 | 長押し → 「編集」→ 状況・試すことを自由入力 |
| 削除 | 長押し → 「削除」→ 確認ダイアログ |

```
「このメソッドを削除しますか？
 この操作は取り消せません。」
[キャンセル]  [削除する]
```

削除しても他データへの影響なし（メソッドは独立したマスタ）。

### 18.3 DB設計（案A採用）

初回ログイン時に `methods_default` テーブルから10件をユーザーごとにコピー。以降は完全にユーザー所有データとして管理。

| テーブル | 用途 |
